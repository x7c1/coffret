# chore: close the spec, concept, and error-type follow-ups left by #25 to #29

## Overview

The last four pull requests (#25 kind-neutral head names, #27 padded control
payloads, #28 the local Index port, #29 the control payload schemas) each
left a short list of small items that their refine passes raised but that
were out of their scope. None needs new design; each is a one-place fix in
the spec register (`docs/spec/`), the concept docs (`docs/concepts/`), the
error types, or rustdoc. This task closes all of them in one PR so the
register and the code stop carrying known loose ends into the transfer-flow
work that starts next. Every decision below is already made — apply it; do
not reopen it.

### Spec register (`docs/spec/`)

- **FM-9 — require the padded length to match, as FM-11 does.** Today the
  meta-section decoder (`backend/crates/domain/coffret-format/src/meta/decode.rs`,
  and `frontend/packages/domain/format/src/meta.ts`) only checks that the
  bytes after the CBOR map are zero; FM-11's control-payload decoder also
  requires the padded length to be exactly the Padmé bucket of the unpadded
  length. Make FM-9 say the same — the meta section's plaintext length is
  the Padmé bucket of the map's length, and a decoder rejects a length that
  is not (so padding can neither smuggle bytes nor mis-size the section) —
  and make both decoders enforce it. Name the failure for its cause, beside
  the existing `NonZeroMetaPadding` (Rust) / its TS code, in the shape the
  control-payload pair (`NonZeroControlPadding` / `ControlPaddingLengthMismatch`)
  already uses. Existing fixtures are all padded exactly to the bucket, so
  the interop set needs no regeneration; add a rejection test for a
  mis-sized tail on each side.
- **FM-15 — say why `prev` is there and what a reader checks.** Add a
  sub-bullet: `prev` is the record's own statement of the head it was
  built on, so replay can confirm record *g* follows head *g − 1* from the
  authenticated payload rather than from the name alone; a reader rejects a
  record whose `prev` is not its header generation minus one, and a record
  at generation > 0 without `prev`. Add the corresponding rejection to
  both decoders and a test each (if the decoders already reject this, the
  test is what is missing).
- **FM-16 — one sentence on what `activation_slot` is for.** Keep the
  name. Beside the existing text, state that on a Storage that mints
  identifiers a reader compares `activation_slot` with the base head's
  `next_commit_slot` and rejects a mismatch (it is the evidence that this
  Snapshot consumed that head's slot, MR-2); on a name-keyed Storage the
  field is absent and the name carries the same evidence (FM-12). No code
  change unless the decoders lack a place for that comparison — if so,
  leave it to the caller and say so in the rule.
- **`object_ref` — one rule stating its semantics.** FM-15 and FM-16 both
  carry `object_ref`; make sure exactly one place (a sub-bullet of FM-15 is
  fine, FM-16 refers to it) states: it is the Storage's own identifier for
  the Container's object, the same value whichever device reads it, kept as
  a cache so a device can fetch without a listing; it is never evidence of
  membership — a listing re-derives it, and a reader that cannot open the
  object named by it falls back to the listing rather than failing the
  replay. If FM-15 already says all of that, touch nothing.
- **CK-9 — two sub-bullets for what the Index port already does.** (a) The
  Index records which checkpoint it adopted (the Snapshot's head
  generation), so a later catch-up knows its starting point without
  re-reading Storage; (b) each device-side Index operation — adopt, apply a
  record, checkpoint — is all-or-nothing: an interrupted operation leaves
  the Index as it was, never half-applied. These describe
  `coffret_usecase::Index` (`SnapshotContent::adopted_from`, the
  conformance suite's atomicity cases); cite nothing new in code.
- **Citation style.** Replace every range citation of the form
  `CK-1 to CK-3` in `docs/concepts/` with the explicit IDs (`CK-1, CK-2,
  CK-3`); do the same in `docs/spec/` wherever such a range appears, so a
  grep for a rule ID finds every reference. (`check_command` gates
  `docs/concepts/`.)
- **One verb for the commit slot.** The register says both "spend" (CP-15,
  CP-16) and "consume" (CP-4, CP-5, MR, KL, the concept docs) for the same
  act. Standardize on **consume** everywhere in `docs/spec/` and
  `docs/concepts/` — it is the majority form — and add "consume (a commit
  slot)" to the Journal concept's Collocations. Code identifiers are not
  in scope.

### Concept docs (`docs/concepts/`)

- **Journal, Keyring, Index Snapshot**: add the one sentence the Container
  concept already has — what the provider still sees despite opaque naming
  is listed under [Storage Object](../storage-object/) — in the same place
  (Domain Rules) and the same wording shape.
- **Index**: align the enumeration of device state with CK-7's three
  groups (mappings, materialized Entries, spool / upload progress) instead
  of the current partial list, and add one sentence saying what the Index
  keeps per Container (kind, ciphertext hash and length, the Storage's
  object reference) so `ContainerSummary` needs no concept of its own.
- **Concept Map** (`docs/concepts/README.md`): one sentence that Journal
  records and activation Index Snapshots form a single head chain under
  `head-<generation>` names, which is what serializes writers (FM-12,
  CP-2) — the map currently walks through Journal and Snapshot without
  saying they share one chain.
- Run the concept-doc litmus test from `docs/concepts/README.md` on every
  concept you touch; do not add rules the spec does not state.

### Error types and docs (code)

- **Keyring-replica digest.** `ControlObjectName::parse`
  (`backend/crates/domain/coffret-model/src/control_object_name/parse.rs`)
  maps a name whose shape is right but whose `set_digest` field is not
  lowercase hex back to `MalformedObjectName`, losing the distinction the
  constructor's `InvalidSetDigest` makes. A reader scanning Storage wants
  to tell "not a control object name" from "a Keyring replica whose digest
  field is corrupt". Make `parse` report the digest case distinctly —
  either surface `InvalidSetDigest` with the offending name attached or
  add a dedicated variant named for the cause — and mirror it as its own
  error code in `frontend/packages/domain/format/src/control/objectName.ts`
  / `errors.ts`. Tests match the variant / code on both sides.
- **`MetaSectionTooLong`** (`coffret-format/src/error.rs`) carries nothing;
  give it the offending length and the limit, the same shape as
  `ControlPayloadTooLong`. Same on the TS side if its code lacks the values.
- **`DecodedControlObject::generation`** doc
  (`coffret-format/src/control/decoded_object.rs`) still says "how many
  times this kind had been rewritten"; FM-13 made generation the position
  in the control history (the head chain for Journal records and activation
  Snapshots, the represented head's generation for ordinary Snapshots, the
  Keyring's own counter). Reword to match FM-13.
- **rustdoc clean under `-D warnings`.** `cargo doc --workspace --no-deps
  --document-private-items` with `RUSTDOCFLAGS=-Dwarnings` must pass (the
  `check_command` runs it): fix the unresolved intra-doc links that appear
  without `--features conformance` (point at the concrete path or drop the
  link) and the ambiguous links under `--document-private-items`, plus
  anything else rustdoc reports.

Documentation, comments, commit message, and PR description are in English.
Keep every existing rule ID stable; no new rule IDs are expected (the
additions above are sub-bullets of existing rules).
