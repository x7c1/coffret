# feat: serve a seeded Library on a local MinIO from one command

## Overview

Working on the explorer's interface needs a Library to look at, and today
every way to get one costs something: `make dev` serves a Library that
somebody first created on Google Drive or S3 and filled by hand, and
`make e2e-it` builds one on MinIO but tears it down again, leaving only
screenshots. There is no Library a person can open in a browser, click
through, change, and come back to the next day without a cloud account.

Add one: a Library on a MinIO container on this machine, created and filled
with a varied set of books and albums on its first start, and kept across
restarts until it is reset on purpose.

### Targets

- `make local` — brings the whole thing up, in the background, and gives the
  terminal back, as `make dev` does:
  1. Starts the MinIO container if it is not running. Its data lives under
     `.tmp/local/` (a bind-mounted directory), so it survives the container
     being removed and recreated. Use the same pinned MinIO image as
     `scripts/e2e-it.sh` (and the same way of creating the bucket), shared
     rather than copied: one place to move the pin.
  2. On the first start only — when `.tmp/local/` holds no Library yet —
     creates the Library with `coffret init --s3 --endpoint … --path-style`
     in a state directory under `.tmp/local/` and seeds it (below). Later
     starts find it and skip straight to step 3.
  3. Starts the server, the explorer's build in watch mode and the
     development host over that Library, and prints the launch file to open,
     as `make dev` does. Reuse `scripts/dev.sh` for this rather than
     reimplementing it; extend it where it has to differ (the state
     directory, and the Passphrase below).
- `make local-down` — stops the three processes and the MinIO container,
  keeping every byte under `.tmp/local/`. `make local-down local` is the
  restart, as `make down dev` is for `dev`.
- `make local-reset` — `local-down`, then removes `.tmp/local/`, so the next
  `make local` creates and seeds a fresh Library.

The ports default to ones `make dev` and `make e2e-it` do not use, so all
three can run side by side, and are overridable as theirs are.

### Passphrase

This Library holds nothing but generated files, so it uses a fixed
Passphrase, written in the script and printed by `make local`, and the server
is started with `--passphrase-stdin` instead of asking on the terminal. That
is the one place this mode differs from `make dev`, whose Passphrase is never
seen by a script, and the header comment says why it is acceptable here and
nowhere else. When the server locks itself after idling, `make local-down
local` brings it back without anything to type.

### Seed

Generated by `coffret-fixtures` (extend it, e.g. with a `--scenario` flag or a
subcommand, keeping its current output as the default), with small image sizes
so that the whole seed finishes in about a minute or two. Every page image
shows its position in its book (drawn as digits, with no font dependency
added for it), so a person can tell at a glance which page the reader is
showing. Then carried in with `map`, `sync` and `freeze` as
`e2e-it.sh` does: books are frozen into Packs, as a book dropped in the
explorer is.

The seed covers at least:

- **Books of different shapes** — a one-page book; a short one (around 10
  pages); a long one (around 300 pages); portrait pages, landscape pages, and
  a book that mixes single pages with two-page spreads; pages named in
  sequence (`001.jpg`), not in sequence (`p1.jpg`, `p10.jpg`, `p2.jpg`), and
  with a cover and other unnumbered names among them.
- **Names** — Japanese names, and names long enough to be truncated in a
  listing, for books and for folders.
- **A series** — a folder of several volumes (`Vol. 1` … `Vol. 12` or the
  like), each a book.
- **Hierarchy and volume** — nesting several levels deep; an empty folder,
  in whatever form the Library can show one (e.g. a top-level folder mapped
  with `map --prefix` and nothing in it yet); and one folder holding a few
  hundred small books, for scrolling and sorting.
- **Photo albums** — a couple of small albums, as `coffret-fixtures` makes
  today.

The seed's layout is described in one place (the generator or a comment
beside it), so a person adding a pattern knows where to add it.

### Documentation

`docs/guides/environments.md` gets a section on the local Library: what it
is for, the three targets, where its data lives, the fixed Passphrase, and
that it needs Docker. Its "What the targets do" table gets the three rows,
and `make help` lists them.
