# build(desktop): derive the app, tray and favicon icons from SVG sources

## Overview

The five files in `backend/crates/apps/coffret-desktop/icons/` are Tauri's
sample icons, put there as placeholders when the desktop app was added. The
tray reuses the window icon (`app.default_window_icon()` in
`src/tray.rs`), so it is the same coloured sample, and the installed app and
the development app (`make desktop-dev`) show the same tray icon and the same
tooltip ("Coffret"): with both running there is no telling them apart until a
menu is opened. The explorer has no favicon
(`frontend/packages/apps/web/` has no `public/`).

This task adds two SVG sources, derives every icon from them with one script,
and gives the development app a badged icon and a tooltip of its own.

### The sources

Both go under `assets/icon/` at the repository root, since they are the
source for the desktop crate and the web app alike. Commit them as given.

### Derivation

Everything else is generated by `scripts/gen-icons.sh`, run by a new
`make icons` target, and committed; running it again rewrites the same bytes.
It needs only tauri-cli (`cargo tauri icon` rasterises SVG itself and is
already required by `make desktop-build`), the shell and python3. Where a
variant is needed the script composes a *derived SVG* in a temp directory
(the source nested in a new `<svg>` with a transform, an overlay or a mask)
and rasterises that. Prior art: `scripts/gen-icons.sh` in x7c1/delta does the
same for the app icon, the `.icns` inset, the dev badge and the favicon;
follow its shape where it fits.

- **Installed app** → `icons/`: `32x32.png`, `128x128.png`,
  `128x128@2x.png`, `icon.ico` and `icon.png` (512 px) from `coffret.svg`;
  discard the store, Android and iOS outputs. List `icons/icon.png` first in
  `bundle.icon` so the embedded window icon is sharp on Linux.
- **macOS `.icns`**: the Dock draws an icon as a rounded square at about
  80 % of the canvas with transparent margins, so take `icon.icns` from a
  derived SVG that scales the source to 80 % and centres it on a transparent
  canvas.
- **Development app** → `icons-dev/`: the same set from a derived SVG that
  overlays a badge on the bottom-right corner — a filled disc
  (`#E5532D`) centred on the centre of the corner arc, ringed in the
  background colour, with a bold "D" in white drawn as paths (no text
  element), legible at 32 px. `scripts/desktop.sh` adds the `icons-dev`
  paths as `bundle.icon` to `DEV_TAURI_CONFIG`, so the development binary
  embeds the badged window icon. `tauri.conf.json` keeps the installed set.
- **Tray** → `icons-tray/`: from `coffret-tray.svg`, 32 px and 64 px PNGs
  (`tray.png`, `tray@2x.png`) in black, the same in white
  (`tray-light.png`, `tray-light@2x.png`, the fill swapped in a derived SVG),
  and the four again for the development app with a one-colour "D" badge:
  a disc in the icon's colour in the bottom-right corner, separated from
  the chest by a transparent ring (mask the chest), with the "D" cut out of
  the disc. Name the files so the four variants (black / white × installed /
  development) are plain from their names.
- **Favicon**: `frontend/packages/apps/web/public/favicon.svg` (a copy of
  `coffret.svg`) and `favicon-32.png`; `index.html` links both
  (`<link rel="icon" type="image/svg+xml">`, the PNG as the fallback). The
  build copies `public/` into the explorer's output, which the explorer host
  already serves with the right content types under the existing
  `img-src 'self'` policy.

Keep the derived SVGs as here-documents in the script and the numbers
(`rx`, the 80 % inset, the badge geometry, the tray sizes) as named variables
at its top.

### The tray

`src/tray.rs` stops using `default_window_icon()` and builds the tray icon
from the `icons-tray/` PNGs compiled into the binary (`include_bytes!`,
enabling tauri's `image-png` feature if needed):

- **macOS**: the black icon, set as a template image
  (`icon_as_template(true)`), so the menu bar draws it black or white for its
  own appearance.
- **Linux**: the white icon. GNOME's top bar is dark in both the light and
  the dark style, and the appindicator tray takes the picture as it is.
- **Development app**: the badged variant and the tooltip "Coffret (dev)".
  Tell the two apps apart by what already tells them apart — the identifier
  (`io.github.x7c1.coffret.dev`, set by `scripts/desktop.sh`), read from the
  app's config — rather than a new flag. Name the identifier in one place.

### Docs

`docs/guides/environments.md`, where the desktop app and the development app
are described: a short paragraph on the sources, `make icons`, that the
outputs are committed, the dev badge and tooltip, and why the tray icon is a
one-colour picture (template on macOS, white on Linux). Mention the `.icns`
inset in one sentence so nobody "fixes" it.
